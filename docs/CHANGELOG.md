# 更新日志

本项目遵循 [语义化版本](https://semver.org/lang/zh-CN/)。

## [0.6.1] — 2026-09-13

**仓库变成了一等公民。** 0.6.0 把文档真的落进了文件夹，但「文档库」仍然只是
provider 的一次性选择 —— 换一个文件夹就把上一个忘了，想切回去只能重新选一遍。
这一版把每个仓库记住、命名、列出来，随时切回来。

### 新增

- **仓库注册表**（`web/js/core/repos.js`）。一个仓库 = 一份文档数据 + 一套属于它
  自己的工作台状态。两类仓库并列：

  | 类型 | 后端 | 说明 |
  |---|---|---|
  | 本地仓库 | `electron` / `fsa` | 电脑上的一个真实文件夹 |
  | 本机文档库 | `local` / `idb` | 浏览器存储，固定一个、不可移除 |

- **四个入口，同一条路径**：

  - **首页**列出仓库卡片，每张显示**名称 + 地址** —— 两个仓库都叫「笔记」时，
    只有地址能把它们分开。「新建本地仓库」走统一的创建流程；
  - **侧栏顶部**一行当前仓库（名字/地址两行，长了省略号截断），点开是仓库浮层；
  - **状态栏**显示当前仓库名，地址在 tooltip 里，点一下同样弹出浮层；
  - **设置页**多了「仓库」一区：切换、重命名、移除，以及新建。

- **创建仓库可以命名**：选完文件夹会问名字，默认填文件夹名。取消命名不算失败 ——
  用文件夹名兜底，不让人白选一次。同一个文件夹选第二次会直接切过去，不重复登记
  （路径比较忽略大小写与结尾的分隔符）。

- **移除仓库不动磁盘上的任何东西**：这是「不再显示它」，不是删数据。重新选那个
  文件夹就能认回来（`.mixmark` 还在，文档原样回来）。本机文档库不允许移除。

- 支持 `--library <文件夹>` 命令行参数：启动即连那个文件夹，并自动登记进仓库列表。

### 改动

- **工作台状态跟着仓库走**：上次打开的文档、展开的文件夹、打开的标签页、
  当前选中的文件夹，全部从全局设置搬进按仓库的存储（`mixmark:workbench:<id>`）。

  判据是「这是数据的一部分，还是人的偏好」—— 前者跟着资料走（换一堆资料就该重新
  算），后者跟着人走（主题、强调色、字体、字号、阅读栏宽、分栏比例、API Key 与
  模型全局共用）。这个划分由用户拍板。

- **启动时以主进程为准**：`--library` 或上次留下的连接都只在主进程那头，
  页面里的记录反而可能过期。所以启动流程先去读主进程的状态，连着的文件夹
  才决定用哪个后端，页面那边顺手把它补登记成仓库。

- `MM.provider.init(preferred)` 多了一个可选的首选后端参数：桌面端可以有多个
  文件夹仓库，光靠固定优先级选不出用户上次待的那一个。首选不可用（文件夹被
  挪走、换到浏览器里打开等）就安静地退回自动选路。

- 状态栏右边从「存储层级」（桌面端 / 本机浏览器）改成**当前仓库名** ——
  用户认得出的是「我在 D:\笔记 里」，不是「我用的是哪个后端」。

- 桌面端新增 `mm:library:openPath`：切换到已经知道的文件夹，不弹对话框。
  和 `pick` 的区别只有「路径从哪来」。

### 修复

- 收编已有文档时跳过 `node_modules` / `.git` 这类目录（0.6.0 的补丁，本次一并发布）。
  把仓库根当文档库时，一个 `node_modules` 能塞进来 676 篇第三方 README。

## [0.6.0] — 2026-09-13

**M4 的第一步：桌面端。** 到 0.5.26 为止，文档库终究躺在浏览器的 localStorage 里
（`file://` 下连 IndexedDB 都用不了），换台机器、清一下浏览器数据就没了。
这一版多出来的那个 `electron` 后端把这件事了结：**文档真的以 `.md` 落在你自己选的文件夹里**。

### 新增

- **桌面端（Electron + NSIS 安装器）**

  - 磁盘层 `desktop/lib/library-fs.js` 是**纯 Node** 的，不依赖 Electron，
    所以能脱离壳单测（`desktop/tools/check-fs.js`，42 项）。
    它对页面暴露的还是那套 KV 接口（`get`/`set`/`remove`/`keys`），
    换后端对上层零影响 —— 这是 M2 定下的分级存储约定第一次真正兑现。

  - 磁盘布局是「索引 + 镜像」：

    ```
    你选的文件夹/
    ├─ 读书笔记.md
    ├─ 论文/提纲.md          ← 虚拟文件夹镜像成真实子目录
    └─ .mixmark/             ← docs.json / folders.json / files.json
    ```

    `.mixmark/` 里的索引是权威，`.md` 是给人看的镜像。**结构一变就对齐一次**：
    改名 → 磁盘文件跟着改名；换文件夹 → 文件挪进对应子目录；删干净 → 空目录也收走。

  - 文件名：中文原样保留（不音译）；`\/:*?"<>|` 与控制字符换成空格；
    Windows 保留名（`CON`/`NUL`/`COM1`…）加下划线；结尾的点与空格去掉；
    重名自动加 `(2)` `(3)`；标题里已经带 `.md` 不会变成 `.md.md`；`.txt` 文档存 `.txt`。

  - 首次连接会**收编**文件夹里已有的 `.md` / `.markdown` / `.txt`（子目录一并建成虚拟文件夹），
    之后不再重复导入。把旧笔记直接丢进文件夹就能用。

  - 原生菜单（文件 / 编辑 / 视图 / 帮助）只转发**命令 id**，页面照常执行 ——
    菜单里的「保存」和工具栏的 Ctrl+S 走的是同一份实现，不会出现两套逻辑对不上。

  - 渲染进程没有 Node 权限（`contextIsolation` 开、`nodeIntegration` 关、`sandbox` 开），
    页面拿到的只有 `preload` 挑出来的一小撮能力。

  - 支持 `--library <文件夹>`：快捷方式带上路径，双击直接开那个库。

  - 应用图标（7 档 ICO）、安装器（可选安装目录、桌面快捷方式）、
    卸载不清用户数据（`deleteAppDataOnUninstall: false` —— 误卸载不该连带毁掉笔记）。

### 修复

这一版修掉的问题里，有五个是**只有把桌面端真跑起来才会显形**的，所以只做浏览器端
自测是抓不到的：

- **新建的文档在磁盘上是一串内部 id，而不是它的标题**（`dmtz9d5xo3lx56.md`）。

  根因在写入顺序：库层是「先写正文、后写索引」（这个顺序本身是对的，
  索引写失败时不会留下一打开就空白的文档）。但磁盘层要定文件名时得看标题，
  而那一刻索引里还没有这条 —— 只能退回用 id 命名。

  改法是给 `set()` 加一个可选的第三参 `meta`：磁盘层优先查索引，查不到就用
  调用方带过来的 meta。其他后端用不上这个参数，忽略即可。

  这个 bug 对桌面端的核心承诺是致命的 —— 「把文档存进你自己的文件夹」，
  结果文件夹里躺着一堆机器名。

- **收编进来的 `.txt` 会在对齐磁盘时被改名成 `.md`**：文件名后缀原来写死 `.md`。
  现在后缀跟着文档格式走，收编时也把格式记进索引（否则对齐时又会改回去）。

- **收编进来的标题带着 `.md` 后缀**（文档树里一半带后缀一半不带）。
  磁盘文件名不受影响，只是标题干净了。

- **改名、换文件夹之后磁盘上的文件不动**：以前只有显式「重新扫描文件夹」才对账。
  现在库层的结构操作（新建 / 改名 / 移动 / 删除）末尾都会调一次后端对齐
  —— 这是**可选能力**，其他后端没有 `sync` 就跳过。

- **删掉文件夹后磁盘上残留空目录**：删除路径漏了对齐，补上了。

- **收编已有文档时会去扫 `node_modules`**：把仓库根（或任何带依赖的目录）选作
  文档库时，第三方包的 README / LICENSE 会被当成用户的笔记一口气收进来 ——
  实测一个 `node_modules` 就塞进 676 篇，文档树直接被淹掉。现在收编会跳过
  `.git` / `node_modules` / `__pycache__` 这一类目录（按目录名比较，任何一层都生效），
  并给数量加了 3000 篇的上限，免得有人误把整个盘当库。

- 选文件夹时点「取消」不会再弹一句技术错误。桥那边取消是抛 `AbortError`
  （已被正确吞掉），这里额外加了一道 `if (!root) return` 的护栏：
  万一哪天取消改成返回 `null`，也不该继续往下走把后端切到一个空库
  —— 那看起来就像数据全丢了。

### 说明

- 打包：`cd desktop && npm run build`（先 `copy-web` 把 `web/` 同步进 `desktop/app/`，
  再 electron-builder 出 `MixMark-<版本>-Setup.exe`）。
- Windows 上首次打包若报 `Cannot create symbolic link`，是 `winCodeSign` 压缩包里
  那两个 macOS 符号链接在作怪（解压需要开发者模式）。把 `darwin` 目录排除掉解到
  `%LOCALAPPDATA%\electron-builder\Cache\winCodeSign\winCodeSign-2.6.0` 即可。
- 安卓端（Capacitor）本次未做。

## [0.5.26] — 2026-09-13

### 修复

- **行引用在真实鼠标点击下完全不能用**（两个症状同一个根因）：
  点行号前的复选框，引用芯片显示「第 NaN–NaN 行」；勾了奇数行再勾偶数行，
  已勾的方块又全部消失。

  根因：CodeMirror 传给的 gutter 事件回调的第二个参数是**视口里的块信息**
  （只有 `from`/`to`/`top`/`bottom`），不是 `@codemirror/state` 那个带
  `number` 的 `Line`。直接读 `line.number` 得到 `undefined`，
  往 `selLines` 里塞了一个 `"undefined"` 键：转成数字是 `NaN`，
  芯片就成了「第 NaN–NaN 行」；而复选框是按行号匹配的，一个都对不上，
  看上去就是「勾选标志消失了」。行号得从 `from` 自己换算。

  另外补了护栏：`toggleLineRef` 拒收非有限数，`lineRuns` 也过滤一遍 ——
  这类幽灵键一旦进状态，排查成本极高。

- **列表正文一片灰白，看不清**（用户报的「- 后面的文字颜色太浅」）：
  `t.list` 落在整个 ListItem 上（连正文一起），而 `mm-syn-marker`
  是给 `-`、`#`、`**` 这类**记号**用的浅灰（约 2:1）。拿它涂整条列表项，
  结果是列表正文比正文还淡。现在不再给 `t.list` 上色，记号本身仍由
  `processingInstruction` 负责。

  实测：修后列表正文回到 `--mm-text-1`，**6 主题 × 8 强调色 48 套配色全部 ≥ 7:1**。

- 拖动标签换位后紧跟着的那一次 `click` 会被当成「点击切换」——
  把标签拖到别处松手，文档也跟着跳了。用 250ms 时间窗抑制，
  而不是布尔标记（标记一旦没被消费就会卡住，反过来吃掉下一次真实点击）。

- **发版前清掉两处「早已不成立」的说法**：`[0.5.17]` 更正过「`file://` 下调不通
  DeepSeek API」这个推断，但只改了 CHANGELOG —— `ai-panel.js` 的头部注释和界面上的
  失败提示仍写着「双击打开必然被浏览器拦下」。实际并不会（接口允许跨域）。
  文案改成「请求没能发出去（网络不通，或被跨域策略拦下）」，不再把它说成必然。

### 改动

- **复选框改成自己画的**：以前用浏览器原生控件，圆角、勾、配色都是操作系统的，
  放在这套配色里像个外来的零件。现在 `appearance:none` 之后边框、圆角、
  勾线全走令牌（`--mm-border-strong` / `--mm-radius-sm` / `--mm-accent` /
  `--mm-text-inv`），换主题时它跟着变。
  审计：勾线在强调色底上 48 套配色全部 ≥ 3:1。

- **悬浮只浮现本行与上下各一行**的复选框，不再整列一起亮。
  整列冒出几十个方块看着像界面出了毛病；三行则明确指出「你在这一行上」。
  勾选过的那些不受影响，鼠标移开也还在。用 CSS `:has(+ ...)` 选上一个兄弟，零 JS。

- **标签页**：
  - 四条边都圆了（以前只圆上两角，但这条工具栏不是浏览器的标签栏，
    底座是浮起来的，圆上不圆下反而露出两个直角）；
  - 高度与侧栏「文档 / 大纲 / 搜索」那一行严格对齐（都是 40px，标签本身 30px）；
  - **可以拖进 AI 区域当引用**（沿用侧栏那套 `text/plain = doc:<id>` 约定）；
  - **可以左右拖动换位置**，用 FLIP 做补间，看着是滑过去的而不是瞬移。

## [0.5.25] — 2026-09-12

### 新增

- **引用机制** —— 让「AI 该看什么」变成看得见、可撤销的一件事。
  三个来路都落成输入框上方同一排芯片，每项带一只小叉：

  | 来路 | 用法 |
  |---|---|
  | **行号左边的复选框** | 编辑模式下鼠标移到行号那一列，每行前面浮现一个方块；点一下就是「重点看这一行」。连着点相邻的行会自动并成一段（中间断开的会分成两条引用，不会多捎上无关的行） |
  | **侧栏拖入** | 文档或文件夹直接拖进 AI 区域，整篇递过去 |
  | **输入框关键词** | 写到「现在的文档 / 这篇文档 / this document」这类说法，自动挂上当前打开的那一篇；把说法删掉，引用也跟着收回 |

  引用内容会**附在这一条用户消息上**并随对话保留 —— 否则下一轮它就不记得用户给它看过什么了。
  整块设了大小上限（8000 字符），不然拖三篇长文档就能把 localStorage 写爆。

- **AI 面板高度可拖**：拖动条压在面板顶边上，上下拖改高度，双击回到默认比例。
  存的是量出来的像素而不是「拖了多少」，换个窗口尺寸也还原得回去。

- **`get_status` 工具**：保存状态、上次保存时间、字数/字符数/行数、光标位置、当前选区、
  视图模式、存储类型与保存路径、文档与文件夹总数。用户问「保存了吗 / 多少字 / 存在哪」
  时它不用猜。

- **5 个结构类工具**：`rename_doc` / `move_doc` / `create_folder` / `rename_folder` / `move_folder`。
  `list_library` 也一并加上了**可读路径**（「笔记 / 期中」），不再只给人看 uuid。

- **结构改动卡片与撤销**：结构改动**不**走「先提案后确认」—— 重命名、移动一眼能看懂、
  也能随手改回去，再插一道确认只会让「帮我理一下文档」变成十次点击。
  代价补在卡片上：每张都带一个「撤销」，让「已生效」不等于「不可挽回」。

- **能力边界的明确说法**：系统提示词里写明「清单之外的事一律做不到，直接告知，
  不要假装完成，也不要给一段教程充数」，并列出做不到的那几类（联网搜索、
  访问文档库以外的文件、发邮件、装插件、代替用户按快捷键）。

### 改动

- 幻觉检测的正则放宽了一档：「已…了」中间隔几个字也要认（
  「已经帮你把结论补进笔记了」这种最典型的写法以前漏掉了），同时把
  重命名/移动/放进这类结构动词也纳进来。仍然不跨句号与逗号 —— 跨过去就是两个不相干的分句。
- 侧栏拖拽的 `effectAllowed` 从 `move` 放宽为 `copyMove`：拖进 AI 面板是「给它看一份」，
  不是「移动文件」。

### 修复

- **撤销链会互相失效**：前一张卡片被撤销后，后面那张指向的对象可能已经不存在了，
  点下去会抛一个没人接的错、卡片永远停在「可撤销」。现在两种失败都接住并说清楚原因
  （文件夹里已经有东西了 / 依赖的东西已经没了）。

## [0.5.24] — 2026-09-12

### 新增

- **主题深化** —— M3 最后一项，之前一直没定范围，现在按「用户能直接看到的
  视觉维度「全部做一遍」来定：
  - **底色主题 3 → 6 套**：白昼、羊皮纸、雾灰（新增）、墨夜、纯黑（新增，
    OLED 真黑）、深海（新增，深蓝底）
  - **强调色 5 → 8 个**：新增紫罗兰、石墨（近中性）、玫红
  - **字体档位 4 档**（新增设置项）：复古衬线 / 现代无衬线 / 打字机 / 典雅。
    界面字体与正文字体**分开选** —— 两者诉求不同：界面 13px 要求一眼认出，
    正文要耐读，可以带书卷气。所以「典雅」的界面中文仍走雅黑、只有正文用楷体。
  - 设置页的**主题选择器换成缩略图网格**：每张卡里的色块自带
    `data-theme` / `data-accent`，是**真渲染**而不是示意图，永远跟真实主题一致

### 改动

- **强调色不再是「逐主题手写覆盖」，改为四档明度**：
  `base`（白底）/ `deep`（浅灰底）/ `warm`（暖底）/ `lift`（深底）。
  以前 5 个强调色 × 3 个主题需要写 5+3+2 组变量，现在 6 × 8 也只写 48 行，
  而且新增强调色不用管主题、新增主题不用管强调色。
  `--mm-accent-weak` / `--mm-accent-ring` 也改成用 `color-mix` 从强调色派生，
  不再一处一处写 rgba。
- 强调色的映射规则**故意不写 `html` 前缀**，这样任意元素带上
  `data-theme` + `data-accent` 就能局部渲染成那套配色 —— 主题缩略图靠的就是这一点，
  不用把色值在 JS 里再抄一份。
- 主题循环快捷键（`Mod+Alt+T`）的遍历顺序改为由浅到深，
  且清单取自 `MM.settings.THEMES`（以前是 shell.js 里写死的一份，漏改过）。
- 导出件现在**带上正文字体**，不再在读者那里变成另一种字体。

- **同步滚动「有时候失效」**。查下来是三个原因叠在一起，都已堵上：

  1. **把自己绑在了 `requestAnimationFrame` 上**（主因）。原本是
     「rAF 节流 → 同步」，而 rAF 只在页面**合成帧**时推进：后台标签页、
     最小化的窗口、不合成帧的内嵌视图里它**一次都不跑** ——
     实测（VS Code 内置浏览器）：0 次/600ms，而 `setTimeout` 正常。
     于是同步整条哑掉。现在改为**直接算 + 时间戳去重**（16ms），
     不再依赖渲染循环 —— 滚动同步本来就该跟手，不需要等帧
  2. **隐藏态污染索引**。预览区 `display:none` 时（切「编辑」模式、进首页）
     `ResizeObserver` 会读到尺寸 0 并触发重测，而 `offsetTop` 隐藏时
     **恒为 0** —— 一整排好索引被写成一排 0，回到分栏后就再也对不上。
     现在测量前先问一句「量得到吗」，量不到就什么都不动
  3. **几何变了没重测**：切模式、改字号 / 正文栏宽 / 软换行都没有重测索引

- 顺带加了两道保险：
  - **滚动时自检自愈**：同步前比对「最后一个块的底边」与滚动内容总高的差值，
    是否还等于上次测量时记下的基准（自校准，不对 CSS 的 padding 做任何假设），
    不一致就立刻重测再同步。图片加载完、公式字体到位这类异步高度变化
    不会再让同步悄悄跑偏
  - 新增 `MM.scrollSync.afterLayout()`：rAF 与 `setTimeout` 双保险，
    谁先到谁执行。所有「等布局稳定后再测量」的地方都改用它
- 新增 `MM.scrollSync.syncFrom('editor' | 'preview')`：允许主动同步一次，
  跳行 / 搜索定位这类程序化滚动之后不必干等用户的滚动事件

## [0.2.0] — 2026-09-11

M2：从「浏览器里的文档库」升级为「可以写进你自己硬盘的编辑器」。

### 新增

**存储层重构**
- 虚拟文档库抽成通用实现 `provider/library.js`，存储后端可插拔：
  同一套增删改查逻辑，换后端即可换介质
- **IndexedDB 后端**（`provider/idb.js`）：http(s) 下自动启用，
  容量从 localStorage 的约 5MB 提到几百 MB
- **本地文件夹后端**（`provider/fsa.js`）：File System Access API，
  文档以 `.md` 明文写进你选的任意目录，可直接被 VSCode / Git 管理；
  目录句柄存进 IndexedDB，下次打开无需重选（权限需点一下重新授权）
  - 支持多级文件夹、新建/重命名/删除、拖拽移动
  - 移动文件夹用「递归复制 + 删除」模拟（FSA 没有 move 原语）
  - 保留循环引用防护：拖到自己或自己的后代上会被拒绝
- 存储选路改为「先异步准备、再判断可用」：候选者可以先读回状态，
  再回答自己能不能用。FSA 只有真的连过目录且权限还在才算可用
- 扫描结果带缓存与失效：`list()` 与 `listFolders()` 常成对调用，
  不加缓存每次刷新索引都要走两遍磁盘
- 设置页新增「存储位置」分组：显示当前介质、列出可切换的其它介质、
  连接/重新授权/重新扫描/断开文件夹

**全文搜索**
- 侧栏新增第三个标签「搜索」，在所有文档的正文里找内容
- 输入防抖 200ms；结果按文档分组，命中片段高亮
- 点击结果直接跳到对应文档的对应行

### 修复

- **选中标签的凹形圆角盖住了搜索框**：凹角是靠 `box-shadow` 向下方多铺 10px 补出来的，
  会越过标签与面板的接缝。标签按钮是定位元素、面板不是，按绘制顺序定位元素更靠上，
  于是那 10px 补色盖在了面板顶部的内容上 —— 搜索框有自己的底色（`--mm-bg-sub`），
  被盖出两个看得见的半圆（文档/大纲页的图标按钮是透明的，所以一直没暴露）。
  给面板更高的层叠顺序（`relative` + `z-index: 1`）即可：溢出的补色被同色面板挡住
  （本来就是重复填色），凹弧本身画在标签行内部，形态不受影响
- **文字选中高光几乎看不见**：原来复用 `--mm-accent-weak`（10% 透明度），
  屏幕上看不出选中了哪里。新增专用令牌 `--mm-selection`（26%），
  用 `color-mix` 从强调色派生，换主题换强调色都自动跟随；
  深色主题 34%、羊皮纸 28%（底色越深越需要浓度）。
  同时把编辑器的非聚焦选区也统一成同一浓度，切到预览区不会「白掉」
- IndexedDB 后端在「键不存在」时会把 `IDBRequest` 对象当成值返回，
  导致索引被判定为损坏并重置。改为等请求自己的 `onsuccess` 而不是事务的 `oncomplete`
- `fsa.js`：修正 `create()` 用「最近修改」猜新建文档的取巧做法（改为按路径精确取回）；
  没有根句柄时给出明确错误而不是 `Cannot read properties of null`

### 工程

- `npm.cmd run check` 新增 CSS 校验：注释配对 + 花括号配平。
  起因是改样式时误删了一个注释结束符，后面六十多行规则整段变成注释，
  而浏览器不报任何错 —— 这类问题必须靠工具抓
- 新增 `npm.cmd run serve` 起本地服务器，用于验证 Tier B 的完整存储能力

### 已知限制

- 本地文件夹只支持 Chrome / Edge，且**必须经 http(s) 打开**
  （`file://` 下该 API 整体不可用，双击 index.html 时自动退回 localStorage）
- 外部程序改动文件夹后需要手动「重新扫描」，未做文件系统监听
- 尚未提供图形化的跨存储迁移向导，目前靠「导出全部为 .md」手动搬运

### 技术决策记录

- **全依赖打包成 IIFE**：`file://` 下浏览器以 CORS 为由拒绝 `<script type="module">`，
  这是「双击可用」这条产品红线的硬约束
- **不用 IndexedDB**：Chrome 在 `file://` 下直接抛 SecurityError，localStorage 是唯一可靠选择
- **同步滚动用行号映射而非百分比**：源码与预览的行高完全不同（10 行代码块可能只占 3 行），
  按比例滚动必然越滚越偏
- **不启用自动补全括号/引号**：写 Markdown 时输入 `**`、`` ` ``、`[` 极为频繁，
  自动补出的右半部分会打乱输入节奏
- **导出 PDF 不引 jsPDF**：中文排版需要嵌入 10MB+ 字体且效果差，
  浏览器自带打印引擎质量更好，还能用「另存为 PDF」

### 修复

- **仅编辑模式下编辑区不铺满、正文被推到中间**
  原先给 `.cm-content` 设了 `max-width` 并 `margin: auto` 做「居中阅读栏」，
  但宽屏下正文被推到中间、行号栏却留在最左边，两者间空出两百多像素，
  看起来像排版错乱。
  现在**编辑区不做居中**：去除宽度上限，正文从行号栏右侧铺满到右边缘。
  阅读栏宽（`--mm-measure`）只作用于预览区 —— 那里是「读」的地方需要控行宽，
  编辑区是「写」的地方，铺满更好用。设置页里该项也已改名为「预览区阅读栏宽」。

### 已知限制

- 浏览器端为单文档库模式，尚不支持打开真实文件夹（M2）
- 导出的 HTML 需要外链 KaTeX 资源，尚未做单文件自包含（M3）
- 移动端布局已适配但未做（M4）
- 中文输入法需人工验证：请在 `tools/experiments/m1-smoke.html` 中实测
